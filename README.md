# Credium

**Team Obsidian · CASCADE '26** — PS 4.2 *The Black Hole Ledger* · Theme 4 *Information Asymmetry*

Purpose-bound NGO escrow where vendors sign their own bills. If an NGO claims the same bill twice — across two donors or two chains — **its own two signatures prove it**, and anyone can freeze the vault. No auditor, no admin key.

Mechanism: **two-signature equivocation freeze**.

> **Everything here is SIMULATED.** Bills, vendors, donors, keys and pledges are synthetic. Chains are local Anvil instances. No real money moves.

---

## The idea

A vendor signs a bill. The NGO signs an *allocation* (how much of that bill to pay, from which vault, on which chain). Each chain validates in isolation — so an NGO claiming 60% on chain A and 60% on chain B goes undetected locally.

But both allocations carry **the same bill nullifier** and are signed by **the same NGO key**. Hand the pair to any vault and it freezes permanently. The fraud proof is generated by the fraud itself.

```
NGO signs alloc(chain A, 6000 bps) ─┐
                                    ├──> sum 12000 bps > 10000 → FREEZE
NGO signs alloc(chain B, 6000 bps) ─┘
```

Anyone can submit the pair. The `watcher/` bot holds no privileges a stranger couldn't also exercise.

### Why the domain omits `chainId`

Normal EIP-712 puts `chainId` in the domain separator so signatures can't cross chains. Credium omits it for allocations and instead puts `chainId` and `donorVault` *inside* the signed struct, checked at release. That's what makes cross-chain equivocation provable — both signatures verify in one place. Replay is blocked separately by the per-chain `usedBps` cap.

## What this does and does not prove

> **It proves a vendor-signed invoice was paid and one bill was claimed twice. It does not prove the well was built.**

Delivery is off-chain and unverified. **We have not verified a GST API and claim none.**

## Quick start

Requires Python 3.11+ and [Foundry](https://getfoundry.sh).

```bash
git submodule update --init --recursive
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cd contracts && forge build && cd ..
bash ops/run_demo.sh
```

Open **http://127.0.0.1:8000/**.

`run_demo.sh` stops old processes, starts Anvil on 31337 and 31338, waits for RPC, deploys, seeds bills, then starts the API.

## Demo steps

| # | Step | Shows |
|---|---|---|
| 1 | Health | Two chains up, contracts deployed |
| 2 | Bills | 100 bills: 70 GREEN / 5 AMBER / 18 FORGED / 7 UNKNOWN |
| 3 | Release a GREEN bill | Both signatures verified, money moves |
| 4 | Try a FORGED bill | Reverts `BadVendorSig` — edited amount breaks the signature |
| 5 | Try an AMBER bill | Reverts `TierNotGreen(1)` — NGO-enrolled ≠ registrar-enrolled |
| 6 | Double-claim attack | Same bill on both chains → watcher submits pair → vaults freeze |
| 7 | Reset | `evm_revert` restores both chains |

Reset is Anvil-only — `evm_revert` doesn't exist on a real network.

## Vendor tiers

| Tier | Meaning | Releaseable |
|---|---|---|
| `GREEN` (0) | Registrar-enrolled, 7+ days old | Yes |
| `AMBER` (1) | Enrolled by the NGO | No — `TierNotGreen(1)` |
| `UNREGISTERED` (2) | Unknown signer | No — `UnknownVendor` |

## Mobile app

`android/app/src/main/java/org/credium/app/Config.kt` holds `DEMO_URL` and `LAN_URL`. The URL is compiled in — changing it requires a rebuild.

```bash
cd android && ./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

The phone shares vault state with the desktop, so it is a second operator, not a viewer.

## Security notes

- **All keys are public Anvil test keys.** Anyone could forge anything.
- **Chains are local** (`127.0.0.1`) — not a testnet, not mainnet.
- **The API is unauthenticated.** Anyone who reaches it can press any button, including Scan, which freezes vaults.
- **The watcher is honest by circumstance, not by permission.**
- Signatures use OpenZeppelin `tryRecover`, which rejects high-`s` malleable signatures — otherwise one valid signature could become two and break the equivocation proof.
